# nanoPlayer 设计系统

面向本地音乐资料库与持续播放的跨端工具。保留深色红黑基线、封面主导内容、紧凑桌面表格与持续可见的播放控制。此系统规范后续开发，不表示提案已实现。

## 使用顺序

先读 AUDIT.md 的问题与证据，再读 RULES.md 的组件契约和 ACCEPTANCE.md 的验收映射。INVENTORY.md 列出源码范围；tokens.json 是可编辑的源值快照，应用尚未从此文件生成 CSS。修改此处不会自动修改产品，落地时必须同步源码、测试与当前视觉基线。

## 视觉基础

正文使用 text，辅助信息使用 muted；panel / panel-raised / surface 区分层级，line 仅作分隔。accent 用于播放、选择和主动作，危险操作同时用明确文案与确认。space-1 至 space-7 是 4/8/12/16/24/32/48px；radius-xs/sm/md/lg 为 4/8/12/16px，pill 为 999px。按钮用 radius-sm；内容卡片用 radius-md。不要靠扩大阴影增加层级。

字体使用系统 sans 栈；桌面正文14、辅助13、最小12、章节18、页面32px；移动正文16、辅助14、最小12、页面28px，phone 页面26px。行高预览采用1.5作为规范建议，并非源码全部选择器的统一计算值。移动 control-sm/md 为44px，桌面小控件36px。图形大小和可点击范围分别验收。

## 内容与图标

导航、空态和错误使用简短中文动词；主题标签保持“系统、浅色、深色”。例如权限丢失显示“重新授权”，不能只写“失败”。删除歌单与删除音频必须明确区分。在线歌词明确说明发送的歌曲信息并由用户启用。源音乐默认只读，iOS 托管目录操作遵守已批准边界。

沿用 lucide-react；图标按钮必须有可访问名称，装饰图标不重复朗读。侧栏使用文字 nanoPlayer，应用图标用于系统入口和封面回退。个人媒体不进入组件示例。
