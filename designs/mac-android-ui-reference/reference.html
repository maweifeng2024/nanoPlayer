nanoPlayer · Mac 与 Android UI 优化参考

2026-10-18 · 独立提案 · 待用户评审 · 不代表产品规范或实施决定

1. 结论与适用范围

建议继续使用当前石墨黑、珊瑚红和文字品牌，在现有导航与播放结构上改善信息层级、内容密度和触摸操作。Mac 负责高效浏览与键盘操作；Android 手机负责单手访问与阅读；Pad 延续桌面结构，按宽度调整列数。

本目录是可选择采用的设计参考。未修改应用源代码、已有设计文档、版本、打包或发布元数据，也未生成安装包。原型内脚本只服务本地设计演示，不属于应用实现。所有曲目、音频信息、歌词与路径均为演示数据，不连接真实音乐库。

2. 如何查看

  • 交互原型：顶部切换 Mac、Android 手机、Android Pad。点击侧栏或底部导航、专辑、歌曲、设置、队列和当前歌曲标题。
  • 对照与设计说明：包含现有耐久基线副本与提案差异。
  • 原型由 index.html、reference.css、reference.js 和 assets/ 组成，无外部字体、CDN 或网络请求。整目录可复制保存。
  • 预览服务：在仓库运行 python3 -m http.server 4311 --directory designs，访问 http://localhost:4311/mac-android-ui-reference/index.html。已有服务运行时不必重复启动。
  • 界面截图仅证明设计原型的展示；不能证明产品已实现，也不能作为原生客户端验收。

4. 视觉方向：安静、有序、保留音乐感

保留的基础

  • 深色默认，珊瑚红只用于播放、当前选中和主要操作。
  • nano 红色加 Player 主文字色；侧栏不加完整 App 图标。
  • Mac：左侧导航、独立内容滚动、固定播放器、可选右侧抽屉。
  • 手机：首页、资料库、歌单三项底部主导航；设置在顶栏。
  • 600–900px Pad：72px 图标侧栏，顺序与桌面一致，保留可访问名称。
  • 主题用“系统、浅色、深色”，三个选项等宽。

可独立采用的建议

编号建议价值取舍与用户决策

5. 各端页面设计

Mac

参考画板为 1200×780，208px 侧栏、72px 顶部工具区、92px 底部播放器，内容区左右 32px。上述几何尺寸是本提案参数，现有 220px 侧栏、88px 播放器可继续保留。

首页使用 190px 封面配 30px 标题和一个主要动作。正文区域四列专辑、两列歌曲分区；资料库集中使用紧凑列表，搜索位于全局顶栏。播放控制保持在窗口下部中央，曲目信息在左、队列和音量在右。

在歌曲列表中，不用整行亮红表达播放状态：使用淡红底与专用标识列。悬停只提升当前可操作目标。长标题单行省略，完整名称应在产品详情/可访问名称中保留。

720px 窄窗口仍属于后续设计验收项：应保留主播放和队列，依次收起音量与辅助控制，并使用可关闭的导航面板；本原型没有完整实现 Mac 窄窗路径，不能直接据此替换现有响应式样式。

Android 手机

参考画板 390×844；20px 内容边距，44px 最小图标热区，歌曲行 72px，44px 封面，16px 曲目标题与13px副信息。搜索占满顶栏剩余空间；迷你播放器与底部导航固定在框架下方，不随内容滚动。

首页封面缩为100px，主标题22px，文案保持短句。资料库分类横向滚动，不强行挤成多行。歌曲列表保留更多按钮，省略时长列。展开播放页自上而下呈现封面、曲目、歌词与定时入口。

产品采用时：必须使用真实 Android 窗口 insets 与系统返回顺序；避免底部手势区挤压迷你播放器。本预览是浏览器设备框，没有模拟真实状态栏、系统导航栏、锁屏媒体控件或虚拟键盘。

Android Pad

参考画板840×820，以72px图标侧栏保留桌面导航顺序。歌曲列表以44px按钮和15–16px主体文字适配触摸。专辑可保留四列；歌曲分区按剩余宽度改为单列，减少信息挤压。

Pad 在1024px以上建议恢复带文字侧栏；600px与分屏、大字体、横竖屏、队列开启时仍需单独验证。原型只提供840px代表画板，不能代替这些断点的完整交付。

8. 采用建议：可以只取其中一部分

建议按三个可选批次评估，而不是整体替换。

  • 低结构影响：文字层级、列表对齐、热区、分隔线、菜单状态与焦点。这一批最适合先试。
  • 中等结构影响：首页最近添加的专辑聚合、设置分组与展开播放页排版。先确认内容组织是否符合使用习惯。
  • 需明确决定：覆盖式队列、背景染色变化、侧栏与播放器几何尺寸。未决定之前保持现有规则。

如果以后决定实施：先选择具体编号和页面，再将确认后的规则纳入现有设计文档，映射已有共享组件和平台边界；之后另行安排实现、完整回归与客户端产物。当前没有执行计划、版本分配或发布命令需要你运行。

9. 交付检查与剩余验证

本次仅检查独立设计文件：HTTP预览、Mac与手机画面、Pad画板、菜单开关、主题、搜索与队列等代表交互；具体结果见 验证记录。未运行产品构建或产品发布门禁，因为应用可执行输入未变化。

若采用，需覆盖：桌面深浅色和720px，手机360/390px，Pad600/840/1024px；长标题、空集合、缺失封面、放大字体、焦点返回、菜单完整顺序、歌词真实性、Android返回/键盘/安全区、原生后台播放与10k曲目响应。视觉原型不能证明这些能力。
