# Android 手机与 Pad 设计及实施计划

日期：2026-09-16 · 修订 3：桌面继承原则及 P1–P5 已获用户确认；完整方案已获用户批准，开发进行中；进度与验证见 STATUS.md。
依据：[移动可行性评估](../MOBILE_FEASIBILITY.md)、当时的 v0.1.7 源码和桌面视觉基线。完整开发已启动；本文件描述目标范围，不代表所有验收项已完成。

## 0. 用户确认的强制约束

- Pad 的功能结构、功能菜单名称和顺序、页面层级及交互严格沿用桌面端。不自行合并、删减、改名、改序或替换交互；移动端冲突必须先提出具体问题，用户确认后才修改。
- 手机和 Pad 的样式、颜色、字体体系、图标、控件、主题与动效共用桌面现有设计。手机可以重新组织布局，不重新设计视觉语言。
- 源码和同版本桌面运行效果为基准，线框仅用于评审。冲突记录须包含桌面行为、移动限制、建议、影响范围、用户决定；未经决定的建议不进入实现。
- 用户已在后续消息明确批准完成手机与 Pad 开发；不再等待原方案批准，新增产品差异仍需确认。

## 1. 建议确认的产品范围

- 同一 Android 应用覆盖手机与 Pad，随可用窗口宽度适配；不是两个安装包。建议应用 ID `app.nanoplayer.android`，最低 Android 10 / API 29，首发 arm64 真机；x86_64 用于模拟器。以上为产品选择，需在技术样机阶段验证。
- 首版以 SAF 用户选择目录为唯一资料库入口，原位置只读引用；允许选择单文件补充。暂不加入 MediaStore 全机扫描、账号/同步、NAS、Android Auto、iOS 或第三方商店自动上传。
- 保留资料库、搜索、专辑/艺术家、歌单、评分、离线 LRC、可选联网歌词、队列和后台播放。联网歌词默认关闭，首次启用明确展示传输的标题、艺术家等元数据。
- MP3、AAC/M4A、FLAC、PCM WAV 是首轮验收格式候选；Vorbis/Opus/ALAC/AIFF 逐格式实测后再声明。无缝与桌面全格式等价不作为首发承诺。
- 首发渠道建议签名 APK 内测与官网下载；AAB 留作 Google Play 后续渠道。当前没有 Android 下载，也不修改网站为“已支持”。

## 2. 手机交互

底部导航固定为「首页 / 资料库 / 歌单」，设置从顶栏进入；迷你播放器固定在导航上方。搜索是资料库顶栏可见入口，可从首页进入。返回顺序：关闭菜单/队列 → 收起正在播放 → 返回详情上一级 → 当前主导航根页，再交给系统；旋转、分屏保留筛选、滚动和播放状态。

| 页面 | 内容及主要操作 | 边界与异常 |
| --- | --- | --- |
| 首次启动 | 品牌、只读说明、添加音乐文件夹 | 取消选择仍停留空资料库；不强制权限、不扫描全盘 |
| 首页 | 延续封面主视觉；最近播放、常听、最近添加纵向排列 | 无歌曲时突出添加文件夹，不展示虚构推荐 |
| 资料库 | 歌曲/专辑/艺术家切换；搜索、排序、文件夹过滤 | 歌曲单列：封面、标题、艺人、时长、更多；点击播放，更多可排队/评分/加入歌单 |
| 专辑/艺术家详情 | 封面、基本信息、播放全部、歌曲列表 | 返回保留原列表位置；缺封面用现有占位资源 |
| 歌单 | 创建、重命名、排序、移除歌曲 | 移除只影响歌单；删除歌单确认；多选模式显式完成/取消 |
| 正在播放 | 封面、标题/艺人、可点击评分、进度、上一首/播放/下一首、模式/歌词/队列 | 拖动只在松手时提交 seek；加载和不可 seek 显示明确状态 |
| 歌词 | 独立全屏层，可切回封面 | 无歌词显示添加/可选查找；查询失败不打断播放 |
| 队列 | 底部面板，当前曲高亮，移除、清空、排序 | 拖动提供上移/下移替代按钮；当前曲移除策略沿用桌面规则并写入测试 |
| 设置 | 文件夹与授权、主题/语言、歌词开关、缓存、版本 | 授权失效提供重新关联；清缓存不删评分歌单；不提供源音频删除 |

迷你播放器：48px 封面 + 两行文本 + 播放/暂停 + 队列，整行点击打开正在播放，按钮独立命中。完整播放器不依赖横滑手势；系统音量键控制音量，输出走系统媒体路由。手机长按同样统一为打开更多菜单，避免与 Pad 语义冲突；多选使用显式入口。

## 3. Pad 严格继承桌面，两端共用视觉

### 功能结构与顺序

按 `src/App.tsx` 当前 navigation 与侧栏定义：

1. 首页（Home）
2. 本地资料库（FolderCog）
3. 歌曲（ListMusic）
4. 专辑（Disc3）
5. 艺术家（MicVocal）
6. 最近添加（Clock3）
7. 播放最多（Headphones）
8. 高评分（Star）
9. 歌单分组：新建歌单（Plus），随后按桌面存储顺序列出歌单（Heart）
10. 底部设置（Settings）

本地资料库不合并进歌曲，不新增“文件夹”顶级菜单，不将歌单分组替换成单一歌单页。页面内菜单、设置分组、上下文菜单、播放器按钮及顺序同样照搬；实施前生成完整桌面→Pad 对照表，不能只比对一级导航。无法在 Android 原样提供的功能先列冲突询问，不静默隐藏。

交互基线来自 `TrackTable.tsx` 等实际组件：单击标题查看详情、双击歌曲行播放、显式播放按钮播放、右键上下文菜单、评分、多选、歌单拖动/上下移动、搜索/排序、抽屉及确认对话框均保持语义。保留鼠标右键，并增加触控长按打开同一更多菜单；不改成单击整行播放或全屏歌词。

沿用桌面侧栏 + 主内容 + 底部播放器 + 可选抽屉，以及现有 220px 侧栏、88px 播放器、320px 抽屉和响应式规则作为实现起点。撤销上一版 Pad <600px 自动切换手机导航、72px 导航栏、200px 侧栏及表格自动双行化方案。Pad 窄分屏隐藏常驻侧栏，内容区域滚动；顶栏导航按钮可临时展开同顺序侧栏，选择后收起，不换成手机底部导航。

### 手机与 Pad 的视觉来源

- `src/styles.css` 为实际 token 与控件样式来源。例如强调色为 `--accent: #e65353`，不是旧线框的 #ff626c。字体沿用同一字体栈和层级关系；按 P3 可增大文字与按钮，保持比例及整体一致性，桌面 token 不直接改写。
- `docs/design/DESIGN_SYSTEM.md` 为规则来源。深色默认，浅色/系统主题、封面环境色、焦点和减少动效均复用桌面。
- 图标逐功能复用现有 `lucide-react` 组件及其状态；不使用字符/emoji 替代。应用图标源为 `docs/design/nanoplayer-app-icon-v3.png`，侧栏品牌仍为文字 nanoPlayer。
- 手机重新布局但复用按钮、卡片、输入框、菜单等视觉；Pad 优先复用整套桌面组件，不复制一套近似外观。

| 编号 | 已确认决定 | 设计规格与验收 |

## 4. 技术边界和持久化

Tauri 2 + React + Rust 保留；Kotlin 原生插件负责 SAF、Media3 ExoPlayer、MediaSessionService。原生服务拥有队列、播放位置、音频焦点和会话事实状态；React 只发送动作并渲染带 revision 的快照，恢复时重新订阅，不在手机沿用 JS 定时切歌。Rust 负责资料库、歌单/评分与可复用业务规则。

协议建议：`PlaybackCommand(commandId, expectedRevision, action)`；`PlaybackSnapshot(revision, sessionId, queue, currentId, positionMs, playing, error)`。命令去重、过期 revision 返回新快照；原生事件记录 sessionId 和序号。计次复用桌面阈值，依据实际播放时长累积，seek 不增加听歌时长；数据库唯一键防止重连重复计次。

**首个技术门槛**：在 WebView 停止执行 JS 的情况下，原生服务独立完成自然切歌、会话检查点和持久化。优先验证原生到 Rust 的生命周期安全入口及单写者数据库队列；若桥接不能可靠常驻，则使用 Kotlin 持久事件日志，Rust 恢复后幂等归并。冻结契约后才做 UI 集成，不能同时让两层无协调地写 SQLite。

资源模型新增稳定 track ID 与 `sourceKind / sourceId / documentId / contentUri / availability`，桌面路径保留；SAF 不转伪路径。迁移采用新增字段/表并备份验证，既有五个迁移不重写。持久 URI 权限只申请读取；重扫以提供者与文档标识关联，失效不自动删歌曲和用户记录，不凭相同文件名合并。

不能 seek 的流可在用户允许后复制到应用缓存：先检查空间，显示大小/进度/取消，失败清理临时副本。建议默认缓存预算 1GiB、LRU 回收，播放中的文件固定不淘汰；大于预算须明确提示。原文件不写回。SD 卡断开、云端离线分别显示不可用原因，重授权/下载后恢复。

前台媒体服务、通知、锁屏、耳机、音频焦点/中断在原生层处理。系统杀进程后恢复队列与位置但不自动播放；用户强制停止后不承诺后台存活。桌面 updater、窗口/菜单、文件 watcher、rodio 按平台隔离。Android 更新依赖同签名 APK/商店，不消费桌面 updater manifest。

## 5. 目录组织

当前就绪目录：`docs/clients/android/`（当前方案、状态与环境说明）、`docs/archive/`（历史线框和验收记录）、`scripts/android/`（环境诊断、构建与模拟器测试）、`packaging/android/`（发布契约）。统一入口 `scripts/release/dispatch.mjs` 选择平台，桌面编排保持兼容。

确认后按功能推进，不提前搬动桌面代码：

- `src/platform/`：平台能力接口及 desktop/android 适配；禁止页面散布平台判断。
- `src/layouts/`：PhoneShell 与共享 Desktop/Pad Shell（导航、页面及菜单共用，平台外壳差异经确认后注入）；原 `library/player/playlists/lyrics` 继续存放共享组件。
- `src-tauri/plugins/nanoplayer-mobile/`：Rust 插件入口、`android/` Kotlin 文件/媒体服务及协议；独立 Android 测试。
- `src-tauri/src/`：共享规则和数据库，桌面/移动入口显式条件编译。
- `src-tauri/gen/android/`：确认后初始化。当前整个 gen 被忽略；届时先评估生成结果，再跟踪必要 Gradle wrapper、配置与入口，精确忽略 build/.gradle/local.properties/密钥，禁止把原生长期源码藏在忽略目录。
- `tests/fixtures/android/`：可再分发格式、损坏文件与 URI 场景清单，不加入个人音乐。

## 7. 验收矩阵

- P1：360/600/840/1024px 分屏切换，侧栏可隐藏及重新访问，宽内容可滚动，播放器持续可用。
- P2：长按一次只弹一次菜单；滚动、拖动手柄、短按不误触；关闭后不误播放。
- P3：触控命中尺寸、字体放大、两种主题、中英文及桌面尺寸不受影响。
- P4：无桌面窗口行为，系统安全区正确，Android 返回先关闭当前覆盖层。
- P5：系统路由、更新渠道、SAF 选择/撤销/重授权各有成功、取消和失败用例。

- Pad：一级导航、子菜单、设置、上下文菜单逐项比对名称、顺序、行为；未经确认的合并、删减、调序或触控替换均为验收失败。
- 手机和 Pad：颜色、字体层级、图标、控件状态与桌面源码及同版本截图对照；不能用近似色或自制图标替代。所有平台差异关联用户确认记录。

- Android 10 最低版本模拟器、Android 13 权限变化、API 35/36 当前目标回归；至少一台 arm64 手机和一台 Android Pad 真机。厂商省电差异至少增加一个不同厂商手机。尚未确认现有测试设备，设备缺失须列为发布阻塞。
- SAF：取消/拒绝、撤销、目录移动、SD 卡拔出、云端离线、重复添加、重扫、重授权；每个文件系统测试前后比较源音频 SHA-256。
- 播放：锁屏 60 分钟跨曲、耳机/蓝牙、音频中断、seek、随机/循环、队列编辑、通知控制、进程重建；区分页面销毁、系统回收和用户强停。
- 数据：从桌面现有 schema 测试非破坏性迁移；Android 旧 APK → 新 APK 安装后评分/歌单/位置保留，跨设备绝对路径不假称可用。
- 性能：1 万曲列表有界渲染；首屏、扫描速率、内存和 60 分钟耗电在指定设备记录基线，A 阶段后冻结指标，不以桌面 Chrome 数据替代。
- 每阶段执行相关 Vitest/Rust/只读测试；浏览器 Playwright 验证布局，Android instrumentation/真机验证原生生命周期，两者证据不可互替。
